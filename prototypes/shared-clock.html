Shared clock prototype

The question. Two people in a session share one clock. Does the model below keep two devices, with different wall clocks and different network delays, on the same clock and the same place in the playlist? What did tree/rules.md get wrong?

  • Every command goes through the session's Durable Object, which stamps it with server time and who sent it. The DO also flips the phase itself when time runs out.
  • A device never reads its own wall clock. It counts with a steady timer and keeps an offset to server time. Every message from the DO carries server time, and the device corrects its offset when it is more than 100 ms off. There is no ping.
  • Each playlist keeps its place across pomos. A video seeks only when the clock changes, and only when it is more than half a second off. Between changes it plays on its own.

This page is throwaway. The middle card stands in for the Durable Object. The two outer cards stand in for two devices. Time runs for real, so the walkthroughs use short phases. Nothing is saved. Version 2: the first version measured the offset once, from the wall clock, and a clock that moved after joining stayed wrong.
