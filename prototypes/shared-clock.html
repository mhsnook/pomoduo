Shared clock prototype

The question. Two people in a session each run their own copy of the clock. Every command (start, pause, nudge, skip) goes through the session's Durable Object, which stamps it with server time and who sent it. Each device measures its offset from server time once when it connects and reads the clock through that offset. The video on each device is expected to sit at "how far into this phase we are". Does this keep two devices, with different wall clocks and different network delays, showing the same clock and the same video position? And what did the model in tree/rules.md get wrong?

This page is throwaway. The middle card stands in for the Durable Object. The two outer cards stand in for two devices. Time runs for real, so set short phases to see a rollover. Nothing is saved.
